## Замечания на будущее

- Лимиты запросов хранятся в памяти каждого из 2 воркеров и сбрасываются при перезапуске: перенести на Redis (уже в TODO).
- Регистрация сообщает, что такой адрес почты уже есть: перебор адресов возможен. Приемлемо для закрытого клуба, но стоит учесть при запуске рекламы.
- Сброса пароля пока нет (в TODO). Делать с одноразовой ссылкой, коротким сроком и без подсказки, есть ли адрес в базе.
- Дампы бэкапов лежат на том же сервере без шифрования: забирать на свой компьютер и хранить зашифрованными.
- Законы подгружаются как XML из официальных источников стандартной библиотекой; для строгости можно перейти на `defusedxml`.
- Запустить `pip-audit` в CI, чтобы такие устаревшие пакеты не накапливались.

## Что проверено и в порядке

- Все маршруты без входа отдают только публичные страницы; остальные ведут на вход или отвечают 404. Админка для не-админов отвечает 404.
- Все POST без CSRF-токена отклоняются (исключения только вебхук Stripe с проверкой подписи и публичный чат без cookie).
- Проверки владельца объекта есть во всех изменяющих действиях (запросы на контакт, интересы инвесторов, встречи, мини-клубы, поездки, лоты, стартапы).
- Контакты скрыты до принятого запроса; публичный чат ничего не хранит.
- Загрузки: изображения проходят проверку и перекодирование, PDF пересобираются и отдаются как скачивание.
- Загрузка чужих сайтов для проверок защищена от SSRF (публичные IP, закрепление адреса, лимиты, проверка каждого редиректа).
- Заголовки: строгий CSP без inline, HSTS, `X-Frame-Options`, `nosniff`, `Permissions-Policy`; cookie `Secure`, `HttpOnly`, `SameSite=Lax`.
- Контейнеры приложения не от root, файловая система только для чтения, база и прочее не опубликованы наружу, `.env` с правами 600, `APP_ENV=production`.
- Раскрытие секретов: ключи только в `.env`, не в образе и не в git.
