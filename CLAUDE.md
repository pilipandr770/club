# CLAUDE.md — Клуб ([Название клуба])

Контекст для Claude Code. Владельцы: два партнёра (технический партнёр и инвестор). Реализация: технический партнёр.
Общение с разработчиком: русский. Идентификаторы в коде: английский. Исходные строки интерфейса: английский (`_("...")`), немецкий — перевод в `translations/de`. Комментарии и коммиты: как договорено в репозитории (по умолчанию немецкий, как в предыдущем проекте).

Полное описание: `ARCHITECTURE.md`.

## Команды
Всё выполняется в контейнерах: `docker compose exec app <команда>`.
- `docker compose --profile dev up --build` — поднять всё локально (Postgres, приложение, Caddy, mailpit)
- `docker compose up -d --build` — на сервере
- `flask seed` — демо-данные; `flask remove-demo`, `flask create-admin <email>`
- `pytest -q` — тесты (офлайн, тестовая БД Postgres)
- `flask db migrate -m "..." && flask db upgrade` — миграции (Flask-Migrate; `upgrade` при старте делает сервис `migrate`)
- `flask i18n extract | update | compile` — переводы (обёртка над `pybabel`)
- `flask close-auctions` — закрытие аукционов (ф4, из планировщика)
- Бэкапы: сервис `backup` (дамп в `./backups` каждую ночь в 03:00 UTC, по воскресеньям с проверкой восстановления, хранение `BACKUP_KEEP_DAYS`); копию на свой компьютер забирает `deploy/backup/pull-backups.sh`
- `flask laws-import | laws-sync | laws-status` — корпус законов внутри клуба (Postgres, pgvector); `laws-sync` раз в неделю из `scheduler`; таблицы `law_*` не бэкапим

## Архитектура (кратко)
- Flask App-Factory (`app/__init__.py`). Blueprints: `public`, `auth`, `member` (`/app`), `admin` (`/admin`), `webhooks`, затем `billing`, `sections`, `startups`, `travel`, `documents`, `auction`.
- Один клуб, много отделов (`Section`). Не мультитенантность.
- Без JS-фреймворка: серверные Jinja-шаблоны + `static/js/app.js`.
- Права доступа и лимиты по тарифам — только через `services/entitlements.py` и `config/plans.py`.
- Время в БД — naive UTC; показ в часовом поясе пользователя (`user.timezone`).

## Правила, которые нельзя нарушать

### Интерфейс и безопасность
- Никаких inline-стилей и inline-скриптов (CSP `style-src 'self'; script-src 'self'`). Только классы из `static/css/app.css`.
- Никаких внешних CDN и шрифтов (DSGVO). Системные шрифты.
- Для будущего иврита используем логические CSS-свойства (`margin-inline-*`, `padding-inline-*`), не `left/right`.
- URL от пользователей — через `utils.clean_url`.
- CSRF во всех POST-формах; webhook и публичный `/api/aiko` — исключения.
- Каждое действие администратора — `audit(...)`. Согласия — только через `record_consent` (append-only).

### Переводы (Babel)
- Любая видимая строка — через `_()` / `ngettext`; на уровне модуля и в моделях — `_l()`. Строки не склеивать и не собирать f-строками.
- В JS строки не хардкодить: брать из `data-`-атрибутов.
- Письма и сообщения в Telegram — на языке `user.locale`.
- В `<html>` всегда верный `lang`; не ставить `translate="no"` (участники пользуются браузерным переводом).
- Контент в БД, который нужно переводить, — через `TranslatableMixin` (`{"de": ..., "en": ...}` с откатом на `de`).
- `LOCALES_ENABLED = ["de", "ru"]`. Русский включён по запросу владельца. Другие языки не включать без решения владельцев.
- Новая строка → `flask i18n extract && flask i18n update`, затем перевод в `de` и `ru`, `flask i18n compile`. Проверки полноты обоих каталогов и подстановок должны проходить.

### Юрисдикции
- Язык интерфейса и юрисдикция — разные вещи. Не выводить одно из другого.
- Собственные документы клуба (Impressum, Datenschutz, AGB, согласия, право отзыва) — всегда по праву Германии/ЕС.
- Юридические инструменты получают юрисдикцию **явным параметром** и показывают её значок и оговорку. Если пакета для страны нет, честно сказать об этом, а не отдавать немецкое право как универсальное.
- Новая страна = новый пакет `app/jurisdictions/<код>/` по интерфейсу `JurisdictionPack`, остальной код не трогаем.
- Инструменты никогда не дают «юридическую консультацию» и не оценивают единичный случай.

### Данные и приватность
- Datenschutzerklärung (`legal/datenschutz_*.html`) обновляем в том же коммите, где появляется новый получатель данных, новая функция с персональными данными или новый срок хранения; при изменении текстов меняем `CONSENT_VERSION` и `LEGAL_UPDATED`.
- Контакты других участников показывать только при `IntroRequest.status == "accepted"`. ИИ-ассистент никогда их не выдаёт.
- Матчинг и видимость в каталоге — отдельные необязательные согласия (по умолчанию выключены).
- Нет скрапинга соцсетей. Ссылки на профили только сохраняем и показываем принятым контактам.
- Публичный ассистент ничего не хранит на сервере.
- Экспорт и удаление данных участника — самообслуживание (`services/gdpr.py`).
- Страна проживания обязательна при регистрации.

### Проверка участников (Stripe Identity)
- Членом клуба (в том числе бесплатного тарифа) можно стать только после проверки личности. Все функции клуба закрыты декоратором `@requires_verified`.
- Участник платит клубу взнос за проверку, Stripe выставляет клубу плату за каждую завершённую проверку. Взнос ≥ расходов.
- В БД только `verification_status`, `verified_at`, `stripe_verification_session_id`. Изображения документов, селфи, номера и даты рождения у себя не храним.
- Статус меняет только подписанный и идемпотентный webhook. Лимит попыток — 3, затем ручной путь.
- Ручной путь (`services/membership.py`): админ, который лично знает человека, подтверждает личность в админке с обязательной пометкой. В БД только метод (`manual`), кто поручился и пометка, ничего из документов. Себя подтвердить нельзя, снятие тоже с пометкой, всё в `audit`.
- Оплата вручную: админ ставит тариф на 1, 3, 6 или 12 месяцев с пометкой (`paid_until`); после срока `User.effective_plan` возвращает `guest`. Права проверять только по `effective_plan`.
- Копию у Stripe стираем через redact: по запросу участника и при удалении аккаунта сразу, иначе по сроку, согласованному с юристом.
- Провайдер за интерфейсом `IdentityProvider`; не привязывать остальной код к Stripe.
- В тексте для пользователей: «проверка личности через Stripe». Без обещаний «нет фейков».
- Отказ по стране документа (`BLOCKED_DOCUMENT_COUNTRIES`) и стране проживания (`BLOCKED_RESIDENCE_COUNTRIES`): Россия, Беларусь, плюс то, что исключает Stripe Identity (CN, CU, IR, KP, SY, оккупированные регионы Украины). Остальные страны принимаются. Список утверждают владельцы; в интерфейсе формулировка без упоминания гражданств.
- Ключи Stripe и секреты webhook только из `.env`; ID продуктов и цен в коде не хардкодить. `flask stripe-setup` идемпотентно создаёт продукты, цены и webhook в текущем аккаунте (тестовом или боевом).
- Реальные документы людей проверяем только на аккаунте компании, не на личном аккаунте разработчика.

### Деньги
- Клуб не хранит деньги участников: только Stripe (подписки, билеты) и Stripe Connect (выплаты продавцам аукциона).
- Webhook идемпотентны. Состояния заказа явные и логируются.
- Ставки аукциона только добавляются (append-only); принятие ставки — под блокировкой строки лота (`SELECT ... FOR UPDATE`, PostgreSQL).

### Docker и развёртывание
- Всё приложение запускается одним `docker-compose.yml`. Второй файл (override) не заводим: различия через `.env` и `profiles`.
- Postgres везде, SQLite не используем. Образ `pgvector/pgvector:pg16`, версии образов фиксировать.
- Наружу публикует порты только `caddy` (80/443). `db`, `redis`, `app` — только внутренняя сеть.
- Контейнер приложения не от root. Секреты только через `.env`, не в образе и не в git.
- Периодические задачи — сервис `scheduler`, а не cron на хосте.
- Бэкапы БД обязательны; восстановление проверяется регулярно.

## Расход ИИ
- Каждый вызов языковой модели идёт через `llm.complete(..., feature="...")`; расход пишется в `ai_usage` (день, функция, модель, токены), без людей и текстов (`services/ai/usage.py`).
- Предохранитель: `AI_DAILY_TOKEN_BUDGET`, `AI_MONTHLY_TOKEN_BUDGET`, `AI_PUBLIC_DAILY_TOKENS` (публичный чат). При исчерпании `AIUnavailable("budget")`, функции уходят на запасной шаблон. Эмбеддинги и речь в лимит не входят.
- Страница `/admin/ai`; новая ИИ-функция обязана передавать свой `feature`.

## Матчинг
`score(A→B) = 0.6·cos(need_A, offer_B) + 0.4·cos(need_B, offer_A)`. Эмбеддинги мультиязычные, профиль можно писать на любом языке. Объяснения совпадений — один пакетный вызов LLM, кэш с хешем версии профиля. Без API-ключа — запасной шаблон. Участникам показываем метку, сырые значения — только администратору. До ~20k профилей хватает памяти; дальше `pgvector`.

## Модули и тарифы
- Модули — в `app/modules/` и в реестре `app/modules/__init__.py`. Новый модуль: пакет с `bp`, запись в `MODULES`, функция в `config/plans.py`, ключ в `ENABLED_MODULES`.
- Доступ — только через `@requires_feature(...)` (`services/entitlements.py`). В шаблонах доступ не проверять условиями.
- Тарифы растут только вверх: каждый включает функции предыдущего. Цены и названия тарифов пока не утверждены.
- Операторы и агенты путешествий — роль `User.role`, не тариф.

## Согласия и контакты
- Публикация профиля в каталоге и участие в матчинге — отдельные добровольные согласия, по умолчанию выключены. Решения принимаются только на `/profile/privacy`, каждое пишется в `consents`.
- Контакт (e-mail) другого участника виден только после принятого запроса на контакт (`services/intros.py`). Лимит — 10 запросов в сутки.
- Подборка и объяснения матчинга не содержат имён, почты и контактов в запросе к LLM.

## Доступ к контенту
- Просмотр контента участников (стартапы, поездки, профили) открыт всем верифицированным, включая гостей.
- Участие (интерес, бронь, публикация) — по тарифу через `requires_feature`.
- Документы, селфи и банковские данные не храним: только статус проверки Stripe.

## Аукцион и админка
- Аукцион: `services/auction_engine.py`. Два режима: повышение (ставки, побеждает последняя) и понижение (голландский: цена падает по времени, побеждает первый). Суммы в центах. Ставки только добавляются, принятие — под `FOR UPDATE`.
- Платежей в аукционе пока нет (ждём юриста). Закрытие лотов: `flask close-auctions` из планировщика.
- Админка `/admin` — только `User.is_admin`, для остальных 404. Каждое действие — `audit(...)`. Администратора нельзя заблокировать или лишить прав самому себе.
- Тестовые участники: `flask seed-test-users` (пароль из `TEST_SEED_PASSWORD`, не работает в production). Домен `@club.test`.

## Отделы
Отдел включается флагом в БД. Отделы запускаются по очереди (см. `ARCHITECTURE.md`, §8). Аукцион и эскроу не включать до проверки юристом.
