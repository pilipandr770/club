# Архитектура клуба — Flask-приложение

Версия 0.2 · черновик · основа: код Main-Power (одно сообщество), расширенный отделами, тарифами, i18n и пакетами законов по странам.

## 1. Принципы

1. **Один клуб, много отделов.** Не мультитенантность. Отдел (`Section`) — это данные: название, описание, события, лента, права доступа по тарифу. Включается флагом, поэтому запускаем по очереди.
2. **Язык и юрисдикция — разные оси.**
   - Язык (`locale`) — на каком языке интерфейс: сейчас только `de`.
   - Юрисдикция (`jurisdiction`) — по какому праву работают юридические функции: сейчас только `DE`.
   - Участник из Израиля или США видит немецкий интерфейс и немецкий пакет законов, но это два независимых переключателя.
3. **Корень — немецкое и европейское право.** Компания клуба в Германии, поэтому собственные документы клуба (Impressum, Datenschutz, AGB, согласия, право отзыва) всегда по немецкому праву и DSGVO, независимо от страны участника. Пакеты законов по странам — это сервис для участников, а не правовая основа самого клуба.
4. **Тарифы решают доступ.** Любая функция проверяется через `entitlements`, а не через разбросанные условия.
5. **Деньги клуб не хранит** (Stripe, позже Stripe Connect).
6. **Приватность по умолчанию:** контакты только после принятого запроса, матчинг и каталог — отдельные согласия, без скрапинга соцсетей.
7. **Только проверенные участники.** Стать членом клуба, в том числе на бесплатном тарифе, можно только после проверки личности в Stripe Identity (см. §10). Клуб не хранит документы.

## 3. Языки (Babel)

### Состояние и план

| Язык | Статус | Комментарий |
|---|---|---|
| `de` | включён | основной, полный каталог |
| `en` | заложен, выключен | первый кандидат на второй язык: понятен участникам во всех четырёх странах и нейтрален; браузерный перевод с английского на русский обычно лучше, чем с немецкого |
| `ru` | заложен, выключен | включать только осознанным решением, из-за вашего соображения про внимание |
| `he` | не сейчас | иврит пишется справа налево; для будущего сразу используем логические CSS-свойства (`margin-inline-start`, `padding-inline`) |

Список включённых языков — в `LOCALES_ENABLED = ["de"]`. Пока он из одного языка, переключатель в интерфейсе не показывается.

### Правила

1. **В коде исходные строки на английском** (`_("Save")`), немецкий — перевод в `translations/de`. Так каталог не придётся менять при добавлении языков, а машинный перевод и инструменты работают лучше. Немецкий текст при этом не теряется: это обычный каталог `de.po`, и Claude Code может его заполнять.
2. Все видимые строки идут через `gettext` или `ngettext`. В Python на уровне модуля и в моделях — `lazy_gettext` (`_l`). Строки не склеиваем и не собираем из f-строк: только `_("Hello %(name)s", name=...)`.
3. **Выбор языка:** `user.locale` → cookie → лучшее совпадение с `Accept-Language` среди включённых → `de`. В URL язык не кодируем (проще и без дублей для поисковиков), позже для публичных страниц можно добавить `/en/`.
4. **Не мешаем браузерному переводу.** Верно ставим `<html lang="de">`, не используем `translate="no"` и не кладём текст в картинки. Текст, который JS подставляет динамически, берём из `data-`-атрибутов (CSP запрещает inline-скрипты).
5. **Контент в базе** (названия услуг, описания отделов, FAQ): поля JSON `{"de": "...", "en": "..."}` через общий `TranslatableMixin` с откатом на `de`.
6. **Письма и уведомления Telegram** отправляются на языке `user.locale`. Браузерный перевод к письмам не применяется, поэтому это важно.
7. **ИИ-ассистент Aiko:** язык интерфейса и язык ответа независимы. Ассистент отвечает на языке вопроса (русский участник может спросить по-русски). Это приватный диалог, на публичные страницы это не влияет.
8. **Матчинг** работает между языками: мультиязычные эмбеддинги (Voyage/OpenAI) уже понимают профили на русском и немецком. Профиль можно писать на любом языке.
9. **Процесс:** CLI-группа `flask i18n extract | update | compile` (обёртка над `pybabel`); тест проверяет, что каталог `de` переведён полностью и компилируется.

## 4. Юрисдикции (законы по странам)

### Идея

Законы — подключаемые пакеты. Каждый реализует один интерфейс:

```python
# app/jurisdictions/base.py
class JurisdictionPack(Protocol):
    code: str                       # "DE"
    name: LazyString                # _l("Germany")
    enabled: bool
    currency: str                   # "EUR"
    law_corpus: LawCorpus           # источник и индекс статей (поиск + цитирование)
    site_checks: SiteCheckRules     # обязательные страницы и сведения для сайта
    disclaimers: Disclaimers        # оговорки для инструментов
```

Сейчас зарегистрирован только `DE`. Чтобы добавить Израиль, США или Великобританию, создаётся `jurisdictions/il/` с тем же интерфейсом, и страна включается флагом. Остальной код не трогается.

### Что зависит от юрисдикции

| Функция | Где берётся юрисдикция |
|---|---|
| Поиск по законам (Aiko) | параметр запроса; индекс статей хранится с колонкой `jurisdiction` |
| Проверка сайта на требования (Impressum и др.) | правила пакета |
| Шаблоны документов | `legal_texts/` пакета |
| Налоги и право отзыва в аукционе (ф4) | пакет страны продавца и покупателя |
| Документы самого клуба | всегда `DE` (см. принцип 3) |

### Поведение в интерфейсе

- На каждом юридическом инструменте показываем значок юрисдикции («Германия») и оговорку.
- Если у страны участника пакета нет, инструмент говорит это прямо («Правовая информация пока только для Германии») и не подсовывает немецкое право как универсальное. Это защищает и участников, и вас.
- Выбор юрисдикции для запроса — отдельное поле, по умолчанию `DE`.

## 5. Данные участника для международной аудитории

- `User.locale` — язык интерфейса и писем (по умолчанию `de`).
- `User.timezone` — часовой пояс (определяется браузером при регистрации). Все даты событий показываются в поясе участника; сейчас в коде жёстко `Europe/Berlin`.
- `Profile.country` — страна, с которой участник себя связывает.
- `Profile.residence_country` — страна проживания (обязательное поле при регистрации, нужно юристу и для налогов, см. §7).
- Валюта клуба — EUR; другие валюты позже через Stripe.

## 6. Тарифы и лимиты

Коротко: матрица тарифов живёт в `config/plans.py`, проверка — `@requires_feature("auction.sell")`, лимиты — счётчик `UsageCounter` (в том числе токены ИИ, привязанные к уже существующей `LLMUsage`). Подробнее — в презентации (слайды 6–8).

## 7. Вопросы к юристу до запуска

1. **Санкции и страна проживания.** Что делать с участниками, проживающими в России и Беларуси, и с платежами оттуда. Как правило, Stripe не обслуживает эти страны. Нужна ясная политика регистрации и условия использования.
2. **Контролёр данных и DSGVO** для участников из Израиля, США и Великобритании (данные хранятся на сервере в ЕС).
3. **Международные потребители в аукционе:** НДС при продаже между странами, право отзыва, налоговая отчётность платформ.
4. **Согласия и профилирование:** оценка влияния на защиту данных (DSFA) для матчинга.
5. **Границы юридических функций:** формулировки оговорок для поиска по законам и шаблонов документов.
6. **Права на код и концепт:** отделить код и тексты, написанные для Main Power, от кода нового клуба.

## 9. Развёртывание (Docker)

Всё работает в контейнерах и поднимается **одним `docker-compose.yml`**. На сервер ничего не ставим, кроме Docker. Postgres используем везде, в том числе на компьютере разработчика: SQLite не нужен, потому что аукцион требует блокировок строк, а `pgvector` понадобится для матчинга.

### Сервисы

```yaml
services:
  db:         # pgvector/pgvector:pg16, Postgres с pgvector на будущее; порт наружу не открыт
  migrate:    # одноразово: flask db upgrade, затем завершается; app стартует после него
  app:        # gunicorn, без root, healthcheck
  scheduler:  # тот же образ, supercronic: sync-events, close-auctions, напоминания, сброс квот
  caddy:      # единственный публикует 80/443; автоматический HTTPS (Let's Encrypt)
  redis:      # лимиты запросов при нескольких воркерах (с фазы 1)
  backup:     # ночной pg_dump в том backups + копия вне сервера
  mailpit:    # profiles: [dev] — ловит письма локально
volumes: pgdata, uploads, backups, caddy_data
```

Порядок старта: `db` (healthy) → `migrate` → `app` → `caddy`.

### Как пользоваться

| Действие | Команда |
|---|---|
| Первый запуск на VPS | `git clone …`, `cp .env.example .env`, заполнить, `docker compose up -d --build` |
| Обновление | `git pull && docker compose up -d --build` (миграции применяются автоматически) |
| Локально | тот же файл; `.env` с `FLASK_ENV=development`, `docker compose --profile dev up --build` |
| Команды приложения | `docker compose exec app flask <команда>` |

### Безопасность и эксплуатация

- Наружу открыты только 80 и 443 (`caddy`); `db`, `redis` и `app` только во внутренней сети Docker.
- Контейнер приложения не от root, файловая система только для чтения, том `uploads` отдельно (фото лотов).
- Секреты только в `.env` на сервере (права 600), в репозиторий не попадают. Версии образов фиксируем, не `latest`.
- Сервер: вход по SSH-ключу, файрвол, fail2ban, автоматические обновления безопасности.
- Резервные копии: ночной дамп, хранение нескольких дней, копия вне сервера и **регулярная проверка восстановления**. Без проверенного восстановления бэкапа нет.
- Сервер в ЕС (Германия): это упрощает DSGVO.
- Телеграм-бот в продакшене работает через webhook на домен; локально опрос (`flask telegram-poll`).

## 10. Проверка участников (Stripe Identity)

**Правило:** членом клуба, в том числе на бесплатном тарифе, можно стать только после проверки личности в Stripe Identity. Документы проверяет Stripe; клуб получает только результат.

### Кто и кому платит
- Участник платит **клубу** разовый взнос за проверку (Stripe Checkout), сумма `[€__]`.
- Stripe выставляет **клубу** плату за каждую завершённую проверку (на британской странице £1,25, первые 50 бесплатно, дальше по объёму). Напрямую участник Stripe не платит: это модель продукта, расход всегда на владельце аккаунта.
- Взнос должен покрывать проверку и комиссию платежа, иначе бесплатные участники дают убыток.
- Порядок оплаты: сначала резерв суммы (`capture_method=manual`), списание после успешной проверки, отмена при неудаче. Так не нужны возвраты. Проверить на реальном сценарии.

### Поток

```
регистрация (почта, пароль, согласия: условия, конфиденциальность, биометрия)
  → подтверждение почты
  → взнос за проверку (Checkout, резерв)
  → Stripe Identity: VerificationSession (создаётся на сервере, metadata: user_id)
  → webhook: verified | requires_input | canceled
  → verified: списание, User.verification_status = "verified", verified_at, доступ в клуб
  → профиль и онбординг
```

### Что хранит клуб
- В БД: `verification_status` (`none | pending | verified | failed | manual`), `verified_at`, `stripe_verification_session_id`.
- Не хранит у себя: изображения документов, селфи, номера документов, дату рождения.
- Копия у Stripe лежит в кабинете клуба (по умолчанию 7 лет). Стираем её через redact спустя `[N дней, решить с юристом]` после успеха (статус уже в нашей БД), а по запросу участника и при удалении аккаунта сразу. Проверить, что остаётся после redact.
- Юридически клуб остаётся **контролёром данных**: Stripe — обработчик и одновременно самостоятельный контролёр. Ответственность за информирование, согласия, удаление и договор об обработке данных лежит на клубе.

### Правила реализации
1. Сессию проверки создаёт сервер только для авторизованного пользователя.
2. Лимит попыток на пользователя (3), затем ручной путь через поддержку.
3. Статус меняет только подписанный webhook, не возврат браузера. Обработка идемпотентна.
4. Все функции клуба (`/app`, API, Telegram-чат) доступны только при `verified`. Непроверенный видит публичные страницы и шаг проверки (`@requires_verified`).
5. Провайдер скрыт за интерфейсом `IdentityProvider` в `services/identity.py`, чтобы можно было заменить Stripe (IDnow, Veriff, Sumsub).
6. Политика конфиденциальности: абзац про Stripe, согласие на биометрию, инструкция по удалению.
7. Реклама: «проверка личности через Stripe», без обещаний «нет фейков».

### Ограничения и открытые вопросы
- Для компании в Германии Stripe Identity пока в публичной бете (на момент проверки): подтвердить доступность в аккаунте компании; разработка идёт в тестовом режиме (см. ниже).
- Stripe не проверяет участников младше 16 лет и людей, связанных с Российской Федерацией. Это закрывается списком принимаемых стран (см. ниже), но страна документа не равна гражданству: двойное гражданство проверка не отследит. Письменный ответ Stripe и формулировку условий — к юристу.
- Небиометрический путь для отказавшихся от биометрии (требование GDPR-практики): ручная проверка человеком. Решить с юристом.
- Дубли: один человек может создать два аккаунта. Хэш номера документа для защиты от дублей юридически сомнителен в Германии.

### Принимаемые документы (решение владельцев)
- Принимаем документы всех стран, кроме закрытого списка (решение владельцев от 19.10.2026): Россия и Беларусь по решению владельцев; плюс страны и регионы, которые Stripe Identity исключает сам (см. ниже). Украина, Швейцария, Норвегия, страны СНГ вне санкций принимаются. Список в настройке `BLOCKED_DOCUMENT_COUNTRIES`, отдельно `BLOCKED_RESIDENCE_COUNTRIES` для страны проживания.
- Ограничения самого Stripe Identity (docs.stripe.com/identity/use-cases): нельзя проверять тех, кто прямо или косвенно связан с Россией, Китаем, Кубой, Ираном, КНДР, Сирией, Крымом, Донецкой и Луганской областями, а также лиц из санкционных списков США, Великобритании, ЕС, ООН. Формулировка «связан» шире страны документа: учитываем и страну проживания, плюс подтверждение участника в условиях.
- Список высокого риска ЕС по отмыванию денег (действует с 29.01.2026) нужен банкам для усиленной проверки, не является запретом для клуба; Украины, Беларуси, Швейцарии, Норвегии в нём нет, Россия есть. Не использовать его как список блокировки без юриста.
- Проверка по стране выдачи документа из отчёта Stripe (уточнить в документации, какие поля доступны). Если страна не в списке: доступ не даётся, резерв взноса отменяется, участнику понятное сообщение.
- Формулировки в интерфейсе и условиях: «принимаем документы этих стран», без упоминания гражданств и национальностей. Юрист проверяет формулировку (общее право о равном обращении AGG и санкционные требования).
- Старт: закрытый запуск среди знакомых из Франкфурта.

### Тест-режим и переход на аккаунт компании
- Разрабатываем и тестируем на тестовых ключах Stripe (песочница), с тестовыми документами.
- Ключи и секреты webhook только из `.env`. ID продуктов и цен в коде не хардкодим. Команда `flask stripe-setup` идемпотентно создаёт продукты, цены и webhook в текущем аккаунте.
- Переход: зарегистрировать компанию, пройти активацию Stripe, включить Identity (проверить доступность для DE), настроить брендинг и политику конфиденциальности, выполнить `flask stripe-setup`, подставить боевые ключи, провести пробную проверку.
- Реальные документы людей проверяем только на аккаунте компании: иначе контролёром данных становится физическое лицо.
- По данным Stripe (страница Великобритании) первые 50 проверок бесплатны: может хватить на закрытый старт. Проверить условия для аккаунта компании.
- Юрлицо (UG или GmbH), банковский счёт и активация Stripe занимают недели и составляют критический путь запуска. Код делается параллельно.

## 11. Решения владельца (19.10.2026)

Эти решения имеют приоритет над предыдущими формулировками документа.

- **Возраст:** членство только **18+**. Дата рождения клубу не нужна: из результата проверки берётся только факт «18 лет и старше». Дату рождения клуб не хранит.
- **Тариф «гость»:** бесплатный, с ограниченными правами. Гость тоже проходит проверку личности: проверку проходят **все** аккаунты без исключений.
- **Проверка личности:** Stripe Identity, за интерфейсом `IdentityProvider`. Если Stripe не подойдёт, заменяется адаптером. Клуб не хранит документы, селфи, номера документов и даты рождения.
- **Санкции:** документы стран под санкциями не принимаются. Список — в `BLOCKED_DOCUMENT_COUNTRIES` и `BLOCKED_RESIDENCE_COUNTRIES`. Страна документа берётся из `document.issuing_country` отчёта Stripe.
- **Тарифы:** обсуждаются отдельно. Механизм (`config/plans.py`, `entitlements`) строится сейчас, цены и состав тарифов — позже.
- **Почта и резервные копии:** настраиваются при деплое. В разработке письма только логируются.
- **ИИ:** Anthropic API, модель `claude-haiku-5-5` (ключ только из `.env`).
- **Референсы:** Main-Power — база для участников, матчинга, ассистента и GDPR (проект владельца, полный доступ). Startups — витрина стартапов для инвесторов (фаза 3). auction7 — аукцион на понижение цены (фаза 4). В auction7 документы сохраняются на диск; этот механизм в клуб не переносится.

## 12. Модули и тарифы (20.10.2026)

Клуб собран из модулей. Модуль можно добавить или убрать через `ENABLED_MODULES` (`.env`), не меняя остальной код. Доступ к модулю задаёт тариф через `config/plans.py` и `services/entitlements.py`.

| Модуль | Что делает | Тариф (рабочий вариант) |
|---|---|---|
| `profile` | О себе: короткий заголовок и текст. Гость может написать о себе и наблюдать за клубом | гость и выше |
| `services` | Встроенные услуги клуба | маленький |
| `travel` | Путешествия: участники бронируют, операторы и агенты работают по своей роли | маленький (уточнить) |
| `startups` | Размещение стартапа для поиска инвестора | средний |
| `auction` | Аукцион (логика на понижение цены, из auction7) | дорогой |

Тарифы: `guest` (гость, бесплатный, с ограниченными правами), `starter` (маленький), `growth` (средний), `premium` (дорогой). Названия-заглушки, цены и состав обсуждаются позже.

Открыто: что означает «искусство» в дорогом тарифе (раздел, ИИ-ассистент или что-то другое). Модуль добавим, когда уточним.

Правила:
- Вся проверка доступа идёт через `requires_feature(...)`, а не условиями в шаблонах.
- Модуль без права доступа в меню не показывается и по прямой ссылке недоступен.
- Выключенный модуль не регистрируется: адрес отвечает 404.
- Операторы и агенты в путешествиях — роль участника (`User.role`), не отдельный тариф.

### Стартапы (модуль `startups`)

- Публикует участник тарифа `growth` и выше (`startups.publish`). Смотреть каталог могут `growth` и `premium` (`startups.browse`).
- Каждый стартап проходит модерацию администратора. Любая правка отправляет его на повторную проверку.
- Инвестор выражает интерес один раз на стартап. Контакт основателя виден инвестору только после принятого интереса (CLAUDE.md, раздел «Данные и приватность»).
- Файлы (презентации) пока не загружаются: их хранение отдельно не решено.

### Правило доступа: просмотр открыт, участие по тарифу (20.10.2026)

- Фото и информация, которые участники выкладывают в клубе, видны всем верифицированным участникам, включая гостей.
- Участие зависит от тарифа: интерес к стартапу, бронь места в поездке, публикация стартапа или предложения.
- Паспорта, селфи, номера документов и банковские данные клуб не хранит: их обрабатывает Stripe, у нас только статус проверки.

### Путешествия (модуль `travel`)

- Совместная поездка создаёт любой участник тарифа `starter` и выше (`travel.book`). Она сразу открыта для записи.
- Предложение публикуют участники с ролью `travel_operator` или `travel_agent` на тарифе `growth` и выше (`travel.offer`). Предложение проходит модерацию администратора.
- Места учитываются под блокировкой поездки. Отмена освобождает место, повторная запись возвращает ту же строку.
- Оплата пока не проводится: цена за человека — ориентир, договорённость о деньгах — отдельно.

### Матчинг: состояние (20.10.2026)

- Формула: 0.6·cos(нужда A, предложение B) + 0.4·cos(нужда B, предложение A). Нужда — «главная задача» и «что ищу», предложение — заголовок, отрасль, «чем занимаюсь», «чем могу помочь», навыки, «о себе».
- Участвуют только проверенные участники с согласием на матчинг, у которых заполнены поля для матчинга.
- Участникам показываем метку, сырые оценки не показываем.
- Объяснения — один пакетный вызов Anthropic (`claude-haiku-5-5`) на все кандидаты. В запрос не попадают имена и почта. Без ключа — шаблон; когда ключ появится, шаблоны пересчитываются.
- **Открыто:** провайдер эмбеддингов. Сейчас стоит лексический (слова с хешированием): детерминированный, без внешних сервисов, видит совпадения слов, но не смысл. Для боевого матчинга нужен семантический провайдер. Выбор влияет на приватность: эмбеддинги и тексты уходят к провайдеру (см. пункт 6 в §7).
- Пороги меток (`gut passend` и т. д.) не откалиброваны; их подберём на реальных данных.
